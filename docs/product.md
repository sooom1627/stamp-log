# Product

プロダクト定義（概要・ビジョン・基盤）。実装チケットは [backlog.md](./backlog.md) を参照する。

# 1. 概要

## 1.1 プロダクト概要

本アプリは、日常の「人に会った」「場所に行った」「何かをした」という体験をスタンプとして記録し、それらを自分だけのラリーとして収集・振り返るモバイルアプリである。

一般的なライフログのように詳細な情報を入力・管理することを主目的とはせず、日常の出来事を「集める」「達成する」という体験へ変換することを重視する。

ユーザーは、日常の出来事を以下の3種類のスタンプとして記録する。

- 人
- 場所
- 行動

記録したスタンプは時系列やカレンダーから振り返ることができ、必要に応じて複数のスタンプをラリーとしてまとめることができる。

## 1.2 プロダクトビジョン

**日常を、自分だけのスタンプラリーにする。**

ユーザー自身が何を集め、何を達成とするかを自由に決められることを基本思想とする。

運営側があらかじめ体験や達成条件を定義するのではなく、ユーザー自身の生活・興味・目標に合わせて記録と収集を行えるプロダクトを目指す。

## 1.3 対象ユーザー

日常の体験を気軽に記録したい個人を対象とする。

特に、以下のようなニーズを持つユーザーを想定する。

- 出会った人を記録したい
- 行った場所を残したい
- 日々行ったことを記録したい
- 旅行や趣味の活動を収集したい
- 自分で決めた目標の進捗を楽しみたい
- 過去の行動を後から振り返りたい

## 1.4 プロダクト原則

本プロダクトでは、以下を優先する。

**記録が簡単であること**

詳細な情報入力を要求せず、思いついたときに短時間でスタンプを残せることを優先する。

**記録そのものと整理を分離すること**

スタンプを作成する時点では分類やラリーへの所属を必須とせず、まず記録を完了できることを優先する。

**ユーザー自身が意味を決められること**

「何を記録するか」「どのようにまとめるか」「何を達成とするか」をアプリ側で過度に制約しない。

**振り返ることが楽しいこと**

単なるデータの保存ではなく、時間の経過とともに自分の行動や経験が蓄積されていく感覚を提供する。

# 2. 基盤

## 2.1 アプリケーション基盤

モバイルアプリとして提供する。

初期開発では以下を前提とする。

- React Nativeを利用する
- iOS / Androidでの利用を想定する
- ユーザーログインを必須としない
- 個人利用を基本とする

## 2.2 ナビゲーション

アプリの主要なナビゲーションは以下の3領域とする。

### ホーム

現在の体験を新しく記録するための起点。

主に以下の操作を提供する。

- 人を記録する
- 場所を記録する
- 行動を記録する
- 最近の記録を確認する

### ラリー・記録

これまで作成したスタンプを確認・整理する領域。

主に以下を扱う。

- 記録一覧
- 人・場所・行動による記録の確認
- ラリー一覧
- ラリー詳細
- ラリーの作成・編集

UI上の名称は開発過程で変更可能とし、「記録」等の簡潔な表現を使用してもよい。

### カレンダー

記録を時間軸で振り返るための領域。

日付ごとに作成されたスタンプを確認できることを目的とする。

## 2.3 基本概念

### スタンプ

ユーザーが記録した1回の体験を表す。

スタンプには以下の種類が存在する。

**人**

「誰に会ったか」を表す。

例：

- 山田さんに会った
- 研究者Aさんに会った

**場所**

「どこに行ったか」を表す。

例：

- 東京駅に行った
- 国立科学博物館に行った

**行動**

「何をしたか」を表す。

例：

- ランニングした
- 映画を見た
- ラーメンを食べた

### ラリー

複数のスタンプを、ユーザー自身が設定したテーマや目的に沿ってまとめたものを表す。

例：

- 今年会った研究者
- 東京の美術館
- 今年やりたいこと
- 京都旅行
- 山手線全駅

1つのスタンプは、複数のラリーに含めることができる。

## 2.4 プライバシー原則

本アプリでは人や位置に関する情報を扱う可能性があるため、個人の記録が意図せず他者へ公開されないことを基本とする。

初期段階では、他ユーザーへの公開・SNS的な共有・ランキング等を必須要件としない。
